# Mutation proof — row 19 isolation e2e can fail for the regression it names
# Surface: the REAL senpi binary against the built omo-senpi plugin bundles.

## The assertion under test
`packages/omo-senpi/src/components/task/engine.ts` passes ONE `createIsolationRuntime()` to both
`createTaskLifecycle` and `createTaskManager`. The e2e's `applied` scenario asserts an isolated child
ran in a clone and merged back.

## Mutation: delete the `isolation,` option from the createTaskManager call, rebuild the bundle
$ perl -0pi -e 's/\n    isolation,\n    runners: \{/\n    runners: {/' packages/omo-senpi/src/components/task/engine.ts
$ docker run ... row19-node24-bun142 node packages/omo-senpi/plugin/scripts/build-extension.mjs   # BUILD=0
$ node packages/omo-senpi/scripts/qa/isolation-e2e.mjs --only applied

{
  "pass": false,
  "failed": [
    "record carries an isolation block",
    "child ran in a clone, not the checkout",
    "merge_result.kind",
    "parent checkout gained hello.txt",
    "the clone directory is gone"
  ]
}

5 of 6 assertions failed. (The sixth, "no leftover clone under the state dir", is vacuously true when
nothing was ever cloned; it guards the applied path's cleanup, not the wiring.)

## Restore: put the option back, rebuild, re-run
$ perl -0pi -e 's/\n    runners: \{ "in-process"/\n    isolation,\n    runners: { "in-process"/' packages/omo-senpi/src/components/task/engine.ts
$ docker run ... build-extension.mjs           # BUILD=0
$ docker run ... build-extension.mjs --check   # CHECK=0
$ node packages/omo-senpi/scripts/qa/isolation-e2e.mjs --only applied
restored pass=true
