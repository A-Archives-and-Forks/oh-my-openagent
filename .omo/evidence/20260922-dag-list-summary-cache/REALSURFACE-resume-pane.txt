Real-surface proof: resuming a DAG-bearing session in an isolated scratch pane.

SCENARIO (identical for both runs, only the binary differs)
- scratch project dir seeded with 710 real checkpoints (68MB) in .omo/senpi-task/dag/runs
- a session persisted by running one real turn, then resumed with --session <id>
- 6 of those runs rewritten to be owned by that session, status "paused", leaseHolderPid set to a
  LIVE process so recovery reports live_lease and skips them: the widget renders them without any
  child agent being spawned. Scenario loaded is self-checked by counting "resuming" rows: 6.
- control = a second scratch pane, same host, no DAG runs at all

METRIC: keystroke -> echo latency (ms). Send a unique token, wait for it to appear, measure.
Chosen because pane "revision" is NOT a freeze oracle - see NOTE below.

BEFORE   binary: omob dev build, omo 2a80b83 (origin/dev, no fix)
  subject 140 144 166  34 111  40   median ~126, max 166
  control  33  44  33  36  42  43   median ~39,  max 44
  subject / control median ratio = 3.2x
  ambient: load 10.34, free 4.1GB

AFTER    binary: omob-dagfix, omo eb04a9a3868595640247cafd252c4c63e1d3c8bc (this PR)
  provenance: omob-dagfix.provenance.json contentSha256
              02396c65267e36cc6489d3fcf93b52dafd7a1f8c7b42e529f05129a2f332818a
  pane banner confirmed "omob-dagfix dev build"; resuming rows: 6
  subject  43  54  41  51  78  51   median ~51, max 78
  control  57  42  44  64  48  54   median ~52, max 64
  subject / control median ratio = 0.98x
  ambient: load 8.75, free 6.9GB

CLAIM: the RATIO, not the absolute milliseconds. Ambient load differed between the two runs (the
control's own median moved 39 -> 52), so absolute numbers are not comparable across runs. What is
comparable is the gap to the control measured in the same run: before the fix a resumed
DAG-bearing session was 3.2x less responsive than a session with no DAG; after the fix it is
indistinguishable from it.

NOTE - two confounds found and discarded rather than reported:
1. herdr "revision" counts SCREEN CHANGES. An idle omo TUI does not repaint, and a DAG whose nodes
   are all completed renders static rows (terminal nodes freeze their elapsed label at completedAt),
   so a perfectly HEALTHY widget also holds revision flat. Two revision samplings were discarded.
2. "omob --session <id>" fails with "No session found" when that session never ran a turn: the
   <uuid>-artifacts directory exists but no <uuid>.jsonl does. The first resume attempt measured
   two idle shells and was discarded.

AMPLIFIER: the stall tracks list() cost, which tracks page-cache warmth - ~105ms warm vs 473ms
cold for the same 710 files. Under memory pressure the page cache cannot hold 68MB, so every frame
pays full disk cost. That is why this defect presented as a memory problem.
